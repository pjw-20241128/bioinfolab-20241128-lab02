## 2-1. 아이콘 정리
 
| 순서 | 아이콘 이름 | 모양 | 하는 일 |
|1|탐색기 Explorer|종이 서류가 겹쳐있는 모양|
파일 및 폴더의 목록을 확인하고 관리할 수 있으며, 이들을 생성, 삭제, 이동 등의 작업을 할 수 있다.|
|2|검색 Search|돋보기 모양|
전체 코드에서 특정 단어 또는 문구를 검색할 수 있고 키워드 검색, 대소문자 구분, 정규식 검색 등을 할 수 있다.|
|3|소스 제어 Source Control|일반적인 '공유(Share)' 아이콘에 가지가 하나 더 있는 모양|
Git을 통한 코드의 Version control을 수행하는 아이콘이다. 변경사항이 있는 파일 확인 및 커밋, 푸쉬 등을 할 수 있다.|
|4|실행 및 디버그 Run and Debug|일반적인 '재생(play) 아이콘에 벌레가 앉아있는 모양|
작성된 코드 실행 및 버그를 확인할 수 있는 디버깅 환경을 제공하는 아이콘이다.|
|5|확장 Extensions|정사각형 블록 네 개가 모여있는 모양으로 하나가 기울어짐|
VS Code 마켓에서 필요한 확장 기능을 검색하고 설치할 수 있는 아이콘으로 확장프로그램을 추가/관리한다. |
|6|테스트 Testing|삼각 플라스크 모양|
작성된 유닛 테스트를 탐색하고 실행하는 패널로 테스트 프레임워크와 연동하여 통과/실패 여부를 확인할 수 있다.|
|7|깃허브 Github|원 안에 고양이가 있는 모양|
깃허브 확장 기능을 통해 Codespace 내부에서 원격 작업들을 관리할 수 있는 패널로 브라우저 이동 없이 Discussions 확인, PR 생성 및 리뷰 등을 할 수 있다. |
|8|파이썬 Python|2마리의 뱀이 서로 꼬인 모양|
설치된 확장 프로그램 python의 환경 설정을 할 수 있는 패널로, 실행 환경 점검 및 환경 변수 구성 등을 관리한다. |

## 2-2. 다. 소스 제어
 숫자의 의미 : 변경사항이 있는 파일
second commit

=> 실행을 활용한 커밋보다 터미널을 활용한 커밋이 더 편리하다고 느꼈다. 파일 또는 폴더에서 변경사항을 저장하는 작업인 커밋의 경우 터미널을 활용한다면, 수정한 뒤 바로 세가지의 코드만 차례로 입력하는 간단한 단계로 이루어진다. 반면에, 실행을 활용한 커밋은 파일을 선택하는 과정 및 메세지 입력 등 추가로 수행해야 하는 단계가 많으며 코드를 실행/수정하다가 패널을 전환해야 하는 번거로움이 있다.
